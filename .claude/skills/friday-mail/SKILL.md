# 금요일 안내 메일

이번 주 질문 파일: `$ARGUMENTS`

## 시작 전에

1. 프로젝트 루트의 `업무맥락.md`를 읽는다. 역할, 순서, 규칙, 예시는 모두 그 파일을 따른다. 이 스킬과 다르면 `업무맥락.md`가 우선이다.
2. 질문 파일을 찾는다. 파일 이름만 받았으면 `내업무/` 안에서 찾는다.
   - 인자가 없거나 파일이 없으면, `내업무/질문_*.md` 목록을 보여 주고 어느 주인지 묻는다. 추측해서 고르지 않는다.
3. 파일 이름의 `MMDD`가 그 주 금요일 날짜다. 메일 제목에는 `M/DD` 꼴로 쓴다 (예: `1031` → `10/31`).
4. 함께 읽는 파일: `내업무/위키_목록.md`, `내업무/안내메일_1017.md`(메일 모양의 기준), `내업무/질문과답.md`(정리 표 모양의 기준).

## 순서

### 1. 질문을 한곳에 모은다
- 한 줄짜리 질문과, 사수에게 한꺼번에 보낸 묶음 안의 번호 질문을 모두 하나씩 센다.
- 원래 질문이 몇 개인지 센다.

### 2. 같은 질문끼리 묶는다
- 표현이 달라도 묻는 게 같으면 하나로 묶는다 (예: "출근은 어디서 찍어요?" / "근태는 어디서 찍어요?").
- 묶은 질문은 두 질문의 뜻을 다 담는 문장으로 다시 쓴다 (예: "법인카드는 어디서, 누구한테 신청해요?").
- 질문이 아니라 개인 사정이나 심경이 담긴 말은 따로 표시해 둔다. 메일에는 넣지 않는다.

### 3. 위키 목록에서 답과 담당을 찾는다
- 답은 `위키_목록.md`의 '내용'에 있는 것만 쓴다. 문장을 다듬을 수는 있지만 내용을 더하지 않는다.
- 질문이 묻는 쪽을 앞에 둔다 (예: "비밀번호를 잊었어요"면 '비밀번호 찾기'를 먼저).

### 4. 위키에 없으면 '확인 필요'
- 위키 목록에 맞는 줄이 없으면 답을 만들지 말고 `확인 필요`로 둔다. 비슷한 페이지로 억지로 끼워 맞추지 않는다.

### 5. 정리 표를 남긴다
`내업무/질문과답.md` 맨 끝에 그 주 섹션을 덧붙인다. 지난 섹션은 고치지 않는다. 모양은 기존 섹션과 같게:

```
## MM/DD 주 (월요일 날짜~금요일 날짜, 원본: `질문_MMDD.md`)

원래 질문 N개를 묶어서 M개로 정리했다.

| # | 질문 (묶은 뒤) | 묶은 원래 질문 | 답 | 위키 위치 | 담당 |
|---|---|---|---|---|---|
...

- 확인 필요: (번호와 질문, 없으면 "없음")
- 메일에 넣은 질문: (번호)
```

- 메일에서 뺀 항목은 '답' 칸에 뺀 이유를 적는다.
- 같은 주 섹션이 이미 있으면 덮어쓰지 말고 사용자에게 어떻게 할지 묻는다.

### 6. 안내 메일을 쓴다
`내업무/안내메일_MMDD.md`로 저장한다. 같은 이름 파일이 이미 있으면 덮어쓰기 전에 묻는다.

- 제목, 인사, 끝인사, 서명은 `안내메일_1017.md`와 한 글자도 다르지 않게.
- 질문 하나에 두 줄: 첫 줄은 `- 질문`, 둘째 줄은 들여 쓴 `답. (위키: 위치, 담당: 역할)`.
- '확인 필요' 질문은 둘째 줄에 `확인 필요`만 쓴다.
- 사람 이름, 질문한 사람(신규 A, 사수 C 등)은 쓰지 않는다. 담당은 역할로만.
- "2. 다음 주 챙길 것"은 질문 파일에 일정이 없으면 `- (이번 주 일정)` 자리표시로 남긴다. 일정을 지어내지 않는다.

## 끝내기 전 점검

- [ ] 모든 질문에 답이나 '확인 필요'가 붙었다 (다 됐다는 기준)
- [ ] 위키에 없는 내용이 답에 들어가지 않았다
- [ ] 메일에 사람 이름이나 질문한 사람이 없다
- [ ] 개인 사정이 담긴 말이 메일에 없다
- [ ] 질문마다 정확히 두 줄이다

## 보고

메일을 보내지는 않는다. 다 쓰면 사용자에게 짧게 알린다:
- 원래 질문 수 → 묶은 뒤 질문 수
- 메일에서 뺀 항목과 이유
- '확인 필요' 목록 (온보딩 담당이 직접 확인할 것)
- "다음 주 챙길 것"을 채워야 한다는 것
- 만든 파일 두 개의 경로
